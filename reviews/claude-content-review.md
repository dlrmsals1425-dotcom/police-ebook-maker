## 1. 상황→판단→행동→확인은 이미 파서에 있다 — 다만 라벨이 고정이다

`js/markdown.js:322`의 `flowMap`이 H2 제목을 6칸 타임라인(flow 블록)으로 묶는다.
`js/model.js:35` `EB.FLOW_LABELS`가 그 6칸의 이름이다.

실측한 `classifySection()` 매핑:

| H2 제목 | 분류 결과 | 비고 |
|---|---|---|
| `## 사건 발생` | incident (0칸) | |
| `## 현장 상황` | situation (1칸) | |
| `## 경찰관 판단` | judgment (2칸) | |
| `## 조치` | action (3칸) | |
| `## 결과` | result (4칸) | |
| `## LESSON LEARNED` | lesson (5칸) | |
| `## 상황` / `## 판단` | situation / judgment | 단독어는 `^앵커$`라 정확히 일치해야 함 |
| `## 행동` | **generic** | 매핑 없음 |
| `## 확인` | **generic** | 매핑 없음 |
| `## 자기점검` | **generic** | 매핑 없음 |
| `## 정답` / `## 해설` / `## 질문` | **generic** | 매핑 없음 |
| `## 배울 내용` / `## 학습목표` | learn | 장 표지용 |
| `## 확인사항` / `## 조치사항` | checklist | |
| `## DO` / `## DON'T` | do / dont | |

결론: "행동", "확인"이라는 단어를 프롬프트 문법으로 쓰면 학습 구조가 그대로 깨진다.
어휘를 다음으로 고정해야 한다.

- 상황 → `## 사건 발생` + `## 현장 상황`
- 판단 → `## 경찰관 판단`
- 행동 → `## 조치`
- 확인 → `## 결과` + 별도 체크리스트 쪽

### 치명적 제약: flow는 항상 6칸을 찍는다

`tokensToBlocks()`의 `flushFlow()`는 `EB.FLOW_LABELS.map(...)`으로 **항상 6개 항목**을 만든다.
3칸만 채우면 나머지 3칸이 **빈 카드로 그대로 인쇄된다.**

실측 (3칸만 채운 입력):

```
1. 사건 발생           본문 비어 있음  <-- 빈 카드가 그대로 인쇄됨
2. 현장 상황           본문 O
3. 경찰관 판단          본문 O
4. 조치              본문 비어 있음  <-- 빈 카드가 그대로 인쇄됨
5. 결과              본문 비어 있음  <-- 빈 카드가 그대로 인쇄됨
6. LESSON LEARNED  본문 비어 있음  <-- 빈 카드가 그대로 인쇄됨
```

무게도 동일하다.

```
6칸 채움 weight = 18
3칸만 채움 weight = 18   (빈칸도 같은 비용 + 빈 카드 인쇄)
```

따라서 "질문 쪽에는 앞 3칸만 보여 주고 뒷 3칸은 답 쪽에서" 같은 설계는 **현재 파서로 불가능하다.**
사례 쪽을 쓸 때는 6칸을 모두 채우거나, 아예 flow를 쓰지 않아야 한다.

## 2. 파서에서 안정적인 문법 (화이트리스트)

아래만 쓰면 파싱이 흔들리지 않는다.

### 2.1 제목 2단계만 쓴다

- `# 제목` = 전자책 페이지 1개 (`parse()`가 H1 단위로 페이지를 끊는다)
- `## 제목` = 페이지 안의 섹션. `classifySection()`이 이걸 보고 특수 블록으로 바꾼다.
- `###` 이하는 의미 없는 소제목(`h-block.lv3`)으로만 떨어진다. 구조에 쓰지 말 것.

### 2.2 장 표지

```markdown
# CHAPTER 01 주취 난동 현장

- 위험을 먼저 분리하고 사실은 나중에 듣는다.
- 처벌 의사와 보호 필요성을 따로 본다.
```

- `isChapterHeading()`이 받는 형식: `CHAPTER 1`, `Chapter 1`, `챕터 1`, `제1장`, `제 1 장`
- 바로 아래 불릿 2~3개가 「배울 것」(learn 블록)이 된다.
- **`<!-- page: chapter -->`는 절대 쓰지 말 것.** 실측 결과 장번호가 비고(`제  장`으로 렌더), learn 블록도 생기지 않고 그냥 bullets가 남는다.

```
===== page: chapter 오용 =====
  p3 [chapter] "현장 도착 전" ch=-  w=3.4
      - bullets
```

### 2.3 페이지 유형 지시자

- 위치: `# 제목` **바로 위 한 줄**. 빈 줄이 하나 껴도 동작한다(실측).
- 섹션 중간에 두면 `takeUntilNextH1()`(`markdown.js:709`)이 **조용히 버린다.**
- 유효값은 5개뿐이다: `case`, `dodont`, `checklist`, `law`, `summary`
- 본문 페이지는 지시자 없이 두면 `content`로 추론된다.
- 주의: 지시자는 그 H1 구역에서 만들어지는 **모든 페이지**에 적용된다. 분량이 넘쳐 "(계속)" 쪽이 생기면 그 쪽도 같은 유형이 된다.

### 2.4 콜아웃 6종

```markdown
> point: ...
> tip: ...
> warning: ...
> law: ...
> example: ...
> summary: ...
```

`> 종류:` 다음 한 칸 띄우고 문장. 한글로 바꾸면 인식되지 않는다. 이 부분은 현재 프롬프트가 정확하다.

### 2.5 체크리스트 그룹명

`## 확인사항 / 조치사항 / 보고사항 / 증거확보 / 후속조치` 는 **하나의 체크리스트 블록에 그룹으로 자동 병합**된다(`markdown.js:466`).

그룹명을 임의로 바꾸면(예: `## 자기점검`) generic으로 떨어져서 **불필요한 heading이 덧붙고 그룹명이 "확인"으로 바뀐다.** 실측:

```
===== 자기점검 = 체크리스트 그룹 =====     ## 확인사항 사용
  [checklist] w=5.9  스스로 점검
      - checklist              (블록 1개, 깨끗함)

===== 자기점검 그룹 이름을 임의로 쓰면 =====  ## 자기점검 사용
  [checklist] w=8.6  스스로 점검
      - heading "자기점검"      (군더더기 제목이 붙음)
      - checklist
```

### 2.6 H2에 쓰면 안 되는 단어

`classifySection()`의 규칙은 **순서대로** 평가되고 `/사례/`는 **부분일치**다. 그래서 H2에 "사례"가 들어가면 무엇이든 example 콜아웃으로 흡수된다.

```
"사례"        -> example
"사건 사례"    -> example
"판단 사례"    -> example
```

`# 가상 사례 · 주취 난동` 처럼 **H1(페이지 제목)에는 써도 안전하다.** H2에서만 금지하면 된다.

## 3. 퀴즈 / 자기점검을 현 기능으로 표현하는 법

### 3.1 정답 숨김(접기)은 Markdown에서 도달할 수 없다

접기 UI(`<details>`)는 law 블록의 `original` 필드 하나뿐인데, 여기에 값을 넣을 Markdown 문법이 없다.
`blockToMd()`는 `## 원문`으로 내보내지만 `classifySection()`에는 "원문" 규칙이 없어 generic으로 떨어진다. **왕복 손실 버그다.**

실측:

```
===== 법령 ## 원문 왕복 =====
  p3 [law] "법령 적용"
      - law {"t":"관련 법령","text":true,"apply":true,"caution":true,"original":false}
      - heading "원문"                   <-- 접기로 안 들어가고
      - paragraph "제8조의2 (긴급임시조치) ..."  <-- 본문에 그대로 노출
```

따라서 **정답은 쪽을 넘겨서 보게 하는 수밖에 없다.** 모바일에서 한 쪽씩 넘기는 현재 리더와는 오히려 잘 맞는다.

### 3.2 번호 목록은 번호가 사라진다

`1. 2. 3.`은 `ol` 토큰으로 잡히지만 `tokensToBlocks()`가 `ul`과 똑같이 `bullets` 블록으로 만들고, `render.js`는 항상 `<ul class="bullets">`로 찍는다(금색 점).

실측:

```
토큰 타입: ol
블록 타입: point,heading,bullets,summary
렌더 목록 태그: <ul class="bullets edit-list">...
번호 살아있나: NO — 번호 사라짐
항목: |즉시 체포한다|거리를 벌린다|확인부터 한다|
```

보기 번호는 **텍스트 안에 `①②③`로 직접 박아야 한다.**

### 3.3 배포 HTML에서 체크박스는 눌리지 않는다

`export.js`의 `stripEditor()`가 `data-act` 속성을 지우고, 리더 클릭 핸들러는 `.box`를 무시한다(`if(e.target.closest('button,a,details,.box'))return;`). 토글 스크립트도 없다.
자기점검 체크리스트는 **인쇄용 네모**로 설계해야 한다. "앱에서 체크해 보세요" 같은 문구를 넣으면 안 된다.

### 3.4 검증된 퀴즈 2쪽 패턴 (lint 0/0/0)

```markdown
# 이 상황이라면 · 주취 난동

> point: 심야 상가 앞. 상대가 길을 막고 고성을 지른다. 무엇을 먼저 하는가?

## 고를 수 있는 것

- ① 즉시 현행범으로 체포한다
- ② 통행인과 거리를 벌린다
- ③ 인적사항부터 확인한다

> summary: 고른 뒤 다음 쪽을 펼친다.

# 그래서 이렇게 한다

> point: ② 통행인과 거리를 벌린다. 설득과 확인은 그다음이다.

## 왜 그런가

- 가까운 거리에서는 말이 통하지 않는다.
- 거리를 벌리면 판단할 시간이 생긴다.

> warning: 조용해졌다는 것은 안전해졌다는 뜻이 아니다.

> summary: 거리를 벌리면 판단할 시간이 생긴다.
```

실측 결과:

```
  [content] w=17.6  이 상황이라면 · 주취 난동
      - point / heading "고를 수 있는 것" / bullets(3) / summary
  [content] w=22.4  그래서 이렇게 한다
      - point / heading "왜 그런가" / bullets(2) / warning / summary
  lint: e=0 w=0 i=0
```

질문 쪽에 `<!-- page: case -->`를 붙이면 안 된다. flow 빈칸 4개가 인쇄된다(1번 항목 참조).

### 3.5 자기점검

```markdown
<!-- page: checklist -->
# 현장을 닫기 전에

## 확인사항
- [ ] 거리를 먼저 벌렸는가
- [ ] 취약 인원을 확인했는가

## 조치사항
- [ ] 사람과 공간을 분리했는가

> summary: 체크하지 않은 항목이 있으면 현장을 닫지 않는다.
```

한 목록 안에서 `- [ ]`와 `-`를 **섞으면 안 된다.** 섞으면 일반 불릿이 빈 체크 줄로 렌더된다. 실측:

```
=== A. 체크리스트 혼용 렌더 ===
  row1: "첫째 항목"
  row2: ""   <-- 빈 줄
```

원인: `collectList()`가 체크박스를 하나라도 보면 목록 전체를 `checklist` 토큰으로 만들지만, 일반 불릿은 객체가 아닌 **문자열**로 담긴다. `render.js`는 `it.text`를 읽으므로 `undefined` → 빈 칸.

## 4. 기존 마스터 프롬프트의 구체적 오류

| # | 위치 | 문제 | 근거 |
|---|---|---|---|
| 1 | `master-prompt.js:273` | "숫자와 순서가 있으면 `1. 2. 3.` 또는 짧은 불릿을 쓴다" | 둘이 동일하게 렌더된다. 번호가 사라짐(3.2 실측) |
| 2 | `:135~158` 사례 페이지 예시 | 예시 자체가 **w=27.0 / MAX_WEIGHT 28**. 여유 1 | point(5)+flow(18)+summary(4). tip 하나만 더해도 "(계속)"으로 분할됨 |
| 3 | `:129` "point와 summary는 거의 모든 본문 페이지에" + `:288` "중간제목 2개 이하" | `paginateBlocks()`의 `hasCore` 자동분할과 충돌. point+summary가 있고 weight≥16인데 다음 블록이 heading/point/flow면 **강제로 쪽이 갈린다** | `markdown.js:620-633` |
| 4 | `:203` 체크리스트 그룹 5개 권장 | 5그룹×2항목 = w 15, summary(4) 더하면 한도 근접. **3그룹이 안전** | `blockWeight()` checklist = 2 + 항목수×1.3 |
| 5 | `:53` "제목에 (계속)을 붙이지 마라" | 정작 파서가 자동으로 붙인다. AI에게 금지할 일이 아니라 **분량을 지켜 분할 자체를 안 만들게** 유도해야 함 | `markdown.js:613` |
| 6 | 전반 | 체크박스 혼용 금지 문구가 없음 | 3.5 실측 |
| 7 | `:243~253` 페이지 유형 지정 | `chapter`가 유효값이 아니라는 경고가 없음 | 2.2 실측 |
| 8 | 전반 | H2에 "사례"를 쓰면 example로 흡수된다는 경고가 없음 | 2.6 실측 |

`prompts/경찰교육전자책_마스터프롬프트.md`는 `js/master-prompt.js`에서 `node tests/build-prompt.js`로 생성된다. **md를 직접 고치면 다음 빌드에서 덮어쓰인다. js를 고쳐야 한다.**

## 5. 8~12쪽 소책자 권장 설계

아래 구조를 실제로 파싱해 검증했다. **총 10쪽, 자동 분할 없음, lint 0/0/0.**

| 쪽 | 유형 | 학습 단계 | 역할 | 실측 weight |
|---|---|---|---|---|
| 1 | cover | — | YAML에서 자동 생성 | — |
| 2 | toc | — | 자동 생성 | — |
| 3 | chapter | 도입 | 장 표지 + 「배울 것」 2~3개 | 6.0 |
| 4 | content | **상황 인식** | 도착 전 확인 / 기본 원칙 | 23.6 |
| 5 | case | **상황 제시** | 6칸 타임라인 전부 채움 | 27.0 |
| 6 | case 또는 content | **판단·행동** | 답과 근거 | 27.0 |
| 7 | dodont | **행동 규범** | 해야 할 것 / 하면 안 되는 것 | 18.6 |
| 8 | checklist | **확인** | 자기점검 3그룹 | 12.5 |
| 9 | law | 근거와 한계 | 조문 취지 + 현장 적용 + 주의 | 13.0 |
| 10 | summary | 정착 | 이것만은 기억하세요 3~5줄 | 4.6 |

학습 사이클: **4(상황 인식) → 5(상황 제시) → 6(판단·행동) → 7(규범 대조) → 8(자기 확인)**

12쪽으로 늘릴 때는 **5-6번 퀴즈 쌍을 한 세트 더 넣는 것**이 구조상 가장 안전하다. 새 페이지 유형을 만들 필요가 없고 무게 분포가 이미 검증되어 있다.

8쪽으로 줄일 때는 7(dodont)과 9(law)를 뺀다. 학습 사이클 자체는 유지된다.

### 검증 출력

```
=== 권장 소책자 구조 파싱 결과 ===
  총 10쪽 (표지·차례 포함)
   1. [cover]
   2. [toc]
   3. [chapter  ] w=  6.0  주취 난동 현장
   4. [content  ] w= 23.6  도착 전 30초
   5. [case     ] w= 27.0  이 상황이라면 · 주취 난동
   6. [case     ] w= 27.0  그래서 이렇게 한다
   7. [dodont   ] w= 18.6  주취 현장 DO / DON'T
   8. [checklist] w= 12.5  현장을 닫기 전에
   9. [law      ] w= 13.0  법령을 현장에 적용하는 법
  10. [summary  ] w=  4.6  이것만은 기억하세요

  lint: error=0 warn=0 info=0
```

### 분량 예산 요약 (MAX_WEIGHT = 28)

| 블록 | weight |
|---|---|
| point | 5 |
| summary | 4 |
| flow (칸 수 무관) | 18 |
| dodont | 8 + 항목수×1.1 |
| checklist | 2 + 항목수×1.3 |
| law | 8 + (text+apply+caution 길이)/140 |
| learn | 6 |
| tip / warning / example | 5 + 길이/120 |
| bullets | 1 + 항목수×1.2 |
| paragraph | 2 + 길이/90 |
| heading (H1 / H2) | 6 / 4 |

실용 규칙: **사례 쪽은 point + flow + summary 외에 아무것도 넣지 않는다**(27/28). 본문 쪽은 point + H2 1개 + 불릿 3~5 + tip/warning 1개 + summary 까지가 한계다.

## 6. Codex 구현 시 분리해야 할 것

### 프롬프트(`js/master-prompt.js`) 수정만으로 해결되는 것

1. 학습 단계 어휘 고정 — 행동은 `## 조치`, 확인은 `## 결과` + 체크리스트 쪽
2. 퀴즈 2쪽 패턴을 페이지 문법 항목으로 추가 (3.4의 검증된 형태 그대로)
3. 보기 번호는 `①②③`를 텍스트에 직접 쓰게 지시 (`1.` 금지)
4. 체크리스트 목록은 **모든 줄을 `- [ ]`로** — 혼용 금지 명시
5. 체크리스트 그룹은 3개까지, 그룹명은 지정 5종에서만
6. 사례 페이지 예시에서 분량 여유 확보 (현재 27/28)
7. `<!-- page: chapter -->` 금지를 명시. 장 표지는 `# CHAPTER 01 제목`만
8. H2에 "사례"라는 단어를 쓰지 말 것 (H1은 허용)
9. 사례 쪽은 6칸을 모두 채우거나 flow를 쓰지 말 것
10. `(계속)` 금지 문구를 "분량을 지켜 분할이 생기지 않게 하라"로 교체
11. 8~12쪽 소책자 표준 구성(5장)을 기본 흐름으로 제시

### 파서(`js/markdown.js`, `js/render.js`) 수정이 필요한 것 — 프롬프트로는 못 고침

1. flow 빈칸 미출력 (`render.js` — text 없는 칸은 렌더에서 제외)
2. `ol` 번호 보존 (`tokensToBlocks` + `render.js`에 ordered 플래그 전달)
3. `## 원문` → `law.original` 왕복 복구 (`classifySection`에 규칙 추가) — 이게 되면 **정답 접기 UI를 한 쪽에서 쓸 수 있다**
4. 혼용 체크리스트 빈 줄 (`collectList` — 문자열 항목도 `{text, checked:false}`로 정규화)
5. `자기점검` / `정답` / `해설`을 `classifySection`에 추가

4번은 데이터 손실 버그이므로 우선순위가 높다. 1·2번은 눈에 바로 보이는 결함이다.
3·5번을 넣으면 퀴즈를 한 쪽에 담을 수 있게 되지만, **현재의 2쪽 구조가 모바일 페이지 넘김과 더 잘 맞으므로 파서 수정 없이도 이번 개선은 완결 가능하다.**
